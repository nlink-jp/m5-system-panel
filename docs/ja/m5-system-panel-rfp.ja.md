# RFP: m5-system-panel

> Generated: 2026-09-26
> Status: Draft — その後の変更は Amendments に記録

## 1. Problem Statement

Mac の負荷（CPU・GPU・メモリ・ネットワーク）を確かめるには、アクティビティモニタや
メニューバーのアイコンを開く必要があり、作業中の画面を占有したり視線を外したりする。
m5-system-panel は、机に置いた M5Stack BASIC を Mac 専用の小さな計器盤にして、
これらの値を常時表示する。Mac 側の常駐アプリ（コンパニオン）が計測して同じ
ネットワーク越しに送り、M5 は描画するだけで、ボタンは表示ページの切り替えにだけ使う。

対象ユーザーは、自分の Mac の負荷を横目で確かめたい開発者（第一に運営者本人）。

本プロジェクトは、2026-09-25 に撤回した m5-notify-deck（汎用の通知表示器、BLE）の
企画をやり直したものである。旧コードは破棄済みで、流用しない。撤回の教訓は
組織 ADR-023 に記録されており、本 RFP はその Phase 1 項目 3・7 を満たすように書く。

## 2. Functional Specification

### Commands / API Surface

構成要素は 2 つ。

| 構成要素 | 形 | 役割 |
|---|---|---|
| M5 ファームウェア | M5Stack BASIC v2.7 用 | 受け取った値を描画する。ボタンでページを切り替える |
| コンパニオン | macOS のメニューバー常駐アプリ（Dock アイコンなし、CLI なし） | 計測して送る。M5 の初期設定を行う |

**M5 の画面（320×240）**

| ページ | 内容 |
|---|---|
| ① 概要 | CPU・GPU・メモリ・ネットワークの現在値と小さな推移グラフを 4 分割で表示 |
| ② CPU | 全体使用率の推移（約 5 分）と、コアごとの棒グラフ（P コア / E コアを色分け） |
| ③ GPU・メモリ | GPU 使用率の推移、メモリの内訳（アプリ・固定・圧縮）、圧迫度、スワップ量 |
| ④ ネットワーク | 上り/下りの推移（自動スケール）、使用中のインターフェース名 |

- ボタン: A = 前のページ、C = 次のページ、B = ①概要へ戻る。ボタンの操作は Mac に送らない。
- 推移の履歴は M5 が 1 秒ごと 300 点持つ（送るのは現在値だけ）。
- 値が 3 秒届かないと「データ待ち」を表示し、グラフに空白を入れる。さらに N 分続くと
  画面を暗くする（Mac のスリープ中に点けっぱなしにしない）。値が届くかボタンを押すと戻る。
- 機器 ID（設定時に作るランダムな短い ID、例 `3F2A`）を画面の隅に常に表示する。
- GPU の値が届かない（Mac 側で取得できない）場合は GPU の表示を消す。

**M5 の設定モード**

- Wi-Fi 設定が無いとき、または **B を押しながら電源を入れて 3 秒**保ったときに入る。
  後者は保存済みの Wi-Fi 設定と鍵を消してから入る。
- 周囲の Wi-Fi を 1 回探した**後で**、設定用 Wi-Fi（SoftAP）を出す。
- 画面に表示するもの: 設定用 Wi-Fi の名前（`m5-system-panel-<機器ID>`）、
  使い捨てのパスワード（設定を始めるたびに作る 12 文字）、「Mac のコンパニオンで設定を続けてください」。
- 家の Wi-Fi に接続できないときは「Wi-Fi に接続できません」とやり直し方を表示する。
  **設定用 Wi-Fi を自動で出すことはしない**（知らないうちに周りから見える Wi-Fi が出るのを避ける）。

**コンパニオンのメニュー**

| 項目 | 内容 |
|---|---|
| 状態 | 接続中（パネル `3F2A`）／探しています／応答がありません／ローカルネットワークの許可が必要です（設定の場所を案内）／未設定 |
| 設定を始める | 設定モードの M5 と同じネットワークにいるときだけ出す。押すと設定の窓を開く |
| パネルの登録を解除 | 保存している機器 ID と鍵を消す |
| ログイン時に起動 | 既定オフ（SMAppService） |
| 終了 | |

**初期設定の流れ**

1. M5 が設定モードで設定用 Wi-Fi を出す。
2. 利用者が Mac の Wi-Fi メニューから設定用 Wi-Fi につなぐ（パスワードは M5 の画面）。
3. コンパニオンが設定モードの M5 を見つけ、メニューに「設定を始める」を出す。
4. 設定の窓で、M5 が探した Wi-Fi の一覧から選ぶ（または手入力）→ パスワードを入れる → 保存。
5. M5 が作った機器 ID と鍵（256 bit）がコンパニオンに渡る。コンパニオンは鍵をキーチェーンに、
   M5 は Wi-Fi 設定と鍵を NVS に保存する。
6. M5 が家の Wi-Fi に接続する。Mac は元の Wi-Fi に戻る。以降は自動でつながる。
7. 設定の窓の最後に、設定用 Wi-Fi を「記憶したネットワーク」から消す方法を案内する。

### Input / Output

**計測値（Mac → M5、1 秒ごと）**

| 項目 | 内容 |
|---|---|
| CPU | 全体使用率、コアごとの使用率とコア種別（P/E） |
| GPU | 使用率（取得できなければ欠損） |
| メモリ | 使用量、搭載量、内訳（アプリ・固定・圧縮）、スワップ使用量、圧迫度（通常・警告・危機） |
| ネットワーク | 主に使っているインターフェース名、受信・送信の速度（B/s） |

**通信**

- 発見: M5 は Bonjour（mDNS）でサービス型 `_m5-system-panel._tcp` を名乗る。
  インスタンス名と TXT レコードに機器 ID を含める。設定モードかどうかも TXT で示す。
- 接続: コンパニオンから M5 へ TCP で接続する（外向きの接続なので、Mac のファイアウォールの許可は不要）。
- 1 行 = 1 フレーム。Mac からは 1 秒ごとに計測値、M5 からは 1 秒ごとに受け取りの応答を返す。
  Mac は応答が 5 秒来なければ「応答がありません」と表示してつなぎ直す。
- **認証と暗号化（通常時）**: 設定で共有した鍵を使い、ChaCha20-Poly1305（RFC 8439）で全フレームを
  暗号化・改ざん検知する。セッションごとに両側が乱数を出し合い、HKDF（RFC 5869）で方向別の
  セッション鍵を導出する。ナンスは方向別の連番で、同じ鍵での再使用を起こさない。
  連番で再送（リプレイ）を捨てる。M5 からの応答にも同じ処理をかけ、Mac は偽のパネルを見分ける。
- **設定時**: 設定用 Wi-Fi（WPA2、使い捨て 12 文字）の中で、Wi-Fi 一覧・Wi-Fi 設定・機器 ID と鍵をやり取りする。
- フレームの具体的な形（テキスト化の方法、フィールド、版）は Phase 1 の形式仕様で決め、実装前にレビューする。
- 形式の版はセッション開始時に確かめ、合わなければ「M5 のファームウェアが違います」と表示する。

**混線の防止（同じネットワークに複数のパネル・Mac がある場合）**

| 場面 | 挙動 |
|---|---|
| Mac A とパネル A、Mac B とパネル B が同じ LAN にある | 各 Mac は、設定で鍵を受け取った機器 ID のパネルにだけ接続する。ほかのパネルは無視する |
| Mac A が誤ってパネル B につなぐ | パネル B は検証できないフレームを捨てる。既存の Mac B との接続はそのまま |
| 同じ ID を名乗る偽のパネル | 応答が自分の鍵で検証できないので、Mac は「接続中」にしない |
| 2 台が同時に設定モード | 設定用 Wi-Fi の名前が機器ごとに違い、1 つの Wi-Fi には 1 台しかいない |
| パネルを別の Mac に付け替える | 設定をやり直すと鍵が作り直され、前の Mac の鍵は無効になる |

- M5 が既存の接続を捨てて新しい接続に切り替えるのは、**新しい接続の最初のフレームが
  正しい鍵で検証できたときだけ**（スリープから戻った Mac の張り直しに対応するため）。

### Configuration

- M5: 設定ファイルなし。Wi-Fi 設定・機器 ID・鍵は設定モードで NVS に保存する。
- コンパニオン: 機器 ID と鍵はキーチェーン、「ログイン時に起動」は SMAppService。
  送信間隔（1 秒）・ネットワークのインターフェース（主に使っているものを自動選択）は固定で、設定項目は持たない。

### External Dependencies

- 外部サービス・API キー・クラウドは使わない。
- M5: arduino-esp32 3.x（ESP-IDF 5.x）に同梱のライブラリ（WiFi、ESPmDNS、Preferences）、
  ESP-IDF 同梱の mbedTLS（ChaCha20-Poly1305・HKDF）、M5Unified（M5Stack 公式）。
  設定はコンパニオンが行うので、Web サーバは載せない。
- Mac: Apple のフレームワークのみ（SwiftUI、Network.framework、CryptoKit、IOKit、Security、ServiceManagement）。
- コミュニティ製のライブラリは使わない（ArduinoJson などを含む）。

## 3. Design Decisions

**言語・構成**

| 側 | 採用 | 理由 |
|---|---|---|
| M5 | Arduino C++ + M5Unified、arduino-cli でビルド | m5-clock・m5-vehicle-logger と同じ作り方で、knowledge の知見（書き込み速度など）が使える |
| Mac | Swift 6（SPM）、SwiftUI の MenuBarExtra（メニュー形式） | メニューは数項目だけで、OS 標準の部品で足りる。兄弟の常駐 GUI と同じ流儀 |

- 1 つのリポジトリに `firmware/` と `mac/` を置く。形式の仕様と見本データを両側で共有するため。
- 計測コードは既存ツールから複製する（共有ライブラリにはしない）。CPU・GPU は load-spinner、
  ネットワークのカウンタ処理（32bit 巻き戻り・1 KiB 丸めへの対処）は net-meter から、
  対応するテストとともに持ってくる。
- GPU は IOKit の IOAccelerator の `PerformanceStatistics` にある非文書キーを読む
  （load-spinner と同じ）。呼ぶ関数は公開 API で、キーが無ければ GPU を欠損として送り、
  M5 は GPU 表示を消す。
- 画面描画は PSRAM が無いため、全画面のバッファを持たず領域ごとに描く（空きメモリは Phase 0 で測る）。

**補完する既存ツール**

- load-spinner（メニューバーで CPU/GPU 負荷を感覚的に見る）、net-meter（IF の通信量）と同じ系統。
  これらは Mac の画面の中、m5-system-panel は画面の外の常設計器という棲み分け。
- 「何が忙しくしているのか」はアクティビティモニタに任せる（load-spinner と同じ線引き）。

**OS が管理する役割（ADR-023 項目 3）: 持たない**

- M5 はキーボード・Bluetooth 機器・通知の受け手のいずれにもならない。Mac から見ると、
  同じネットワーク上の TCP の相手でしかない。
- コンパニオンが OS から得るのは「ローカルネットワークの許可」だけ（§5）。

**伝送に Wi-Fi を選んだ理由と却下した案**

| 案 | 却下の理由 |
|---|---|
| USB シリアル | BASIC の ESP32 は USB を持たず、USB のデータ経路は CH9102 → UART0 の 1 本だけで、デバッグ・書き込み用のポートに同居する。起動ログの混入、DTR/RTS による再起動や書き込み待ち停止、書き込みツールとの取り合い、ほかの ESP32 ボードを開いてしまう危険を構造的に避けられない |
| BLE | 撤回した m5-notify-deck の失敗領域（ライブラリの既定、OS の振る舞い）に再び踏み込む |

**Wi-Fi の設定方法で却下した案**

| 案 | 却下の理由 |
|---|---|
| TF カードの `config.json` | 運営者の実測で、Mac から FAT32 の TF カードに書き込めない（読めるが書けない）。Windows VM 経由でしか書けず煩雑 |
| ブラウザの設定ページ（192.168.4.1） | 鍵を安全に Mac のコンパニオンへ渡せない（URL に載せるとブラウザの履歴に残る） |
| ログインページの自動表示（キャプティブポータル） | 規格（RFC 8908/8910）は HTTPS と IP 直書きの禁止を求め、M5 では満たせない。残る手段（DNS をすべて M5 に向ける）は Apple が判定方法を公開しておらず、ADR-023 に照らして前提にできない |
| Espressif 公式のスマホアプリ / WPS / ボタン 3 つでの文字入力 | それぞれ、BLE の再導入とスマホが必要／ルーターで無効なことが多い／入力が非常につらい |

**なりすまし・混線への対処で却下した案**

| 案 | 却下の理由 |
|---|---|
| 同じ LAN からの偽装を受け入れる | 計器として信用できなくなる（運営者の判断） |
| 初回接続時に M5 に番号を出し Mac で入力（AirPlay 型） | 盗聴・中間者に耐える鍵交換に PAKE（SRP・SPAKE2+ 等）が必要だが CryptoKit に無く、暗号処理の自作になる |
| 改ざん検知だけ（暗号化なし） | 手間はほぼ同じなので、中身も隠す |

**対象外**

- 通知の表示、温度・ファン（非公開の SMC 経由でしか取れない）、プロセス一覧
- M5 から Mac を操作すること
- IP アドレスの手入力、企業向けの Wi-Fi 認証（802.1X）、見えない SSID、5 GHz
- 1 台の Mac で複数パネル、1 枚のパネルを複数の Mac で共有（どちらも混線はしないが機能として提供しない）
- M5 側の設定画面、iPhone などからの設定
- macOS 以外の OS、Intel Mac

## 4. Development Plan

### Phase 0: 前提の実測（設計確定の前）

ADR-023 に従い、文書に書かれていない振る舞いは実機で観測してから設計を固める。
結果は ADR にまとめ、§7 の状態表の「Phase 0」行を確定させる。

1. Wi-Fi と描画を同時に動かしたときの M5 の空きメモリ
2. 設定の流れ: 設定用 Wi-Fi への参加 → Mac が元の Wi-Fi に戻るか → 「記憶したネットワーク」への登録と消し方
3. Bonjour での発見と、ローカルネットワークの許可ダイアログ（許可・拒否の両方の経路、`open` で起動）
4. スリープ・起床の後の TCP 接続の状態と、M5 側での接続の切り替え
5. M5 の電源を抜いたとき、Mac が 5 秒以内に気づくか
6. この Mac で GPU のキーが読めるか
7. M5 のハードウェア乱数が鍵の生成に使える条件（文書の確認と、Wi-Fi 有効時の動作）

レビュー: ADR と状態表を、Phase 0 の区切りでレビューする。

### Phase 1: Core

- 形式の仕様（フレーム、版、暗号の使い方、設定時のやり取り）と、両側共通の見本データ
  （既知解。RFC 8439/5869 のテストベクトルを含む）。**実装の前に仕様だけをレビューする**
  （ナンスを再使用しないことを RFC 8439 と照合する独立検証を含む）。
- Mac: 計測（CPU・GPU・メモリ・ネットワーク）、発見・接続・再接続、暗号、設定の窓、メニュー。
- M5: 設定モード、家の Wi-Fi への接続、mDNS、受信・検証・応答、①概要ページ、データ待ち表示。
- テスト: Mac 側は計測・形式・暗号・状態遷移を単体テストで確認する。M5 側は形式と暗号を
  実機のテスト用スケッチで見本データと照合する。混線の場面は、Mac 上の擬似パネルで再現する。
- 実機での通し試験（最終コードで）。

### Phase 2: Features

- ②〜④ページ、ボタン、画面を暗くする処理、ログイン時起動、パネルの登録解除。
- 単独でレビューできる。

### Phase 3: Release

- README（英・日）、AGENTS.md、CHANGELOG。
- コンパニオンの Developer ID 署名・公証（兄弟の常駐 GUI と同じ手順）、Homebrew cask。
- ファームウェアの配布: Arduino 環境が無くても書き込めるよう、統合した `.bin` と esptool の手順
  （書き込み速度は knowledge の実測どおり明示する）。
- lab-series への統合、org カタログの更新、check-org.sh。

## 5. Required API Scopes / Permissions

- **macOS のローカルネットワークの許可**（macOS 15 から。TN3179）。初回の Bonjour 探索・接続時に
  OS がダイアログを出す。Info.plist に `NSLocalNetworkUsageDescription` と
  `NSBonjourServices`（`_m5-system-panel._tcp`）を書く。
  - 拒否された場合は、メニューに許可が必要な旨と設定の場所を表示する。
  - **この許可は macOS では未設定の状態に戻せない**（TN3179）。
- キーチェーン: 自分のアプリの項目だけを使う（追加の権限は不要）。
- サンドボックスは使わないので entitlement は不要。
- 外部サービスの OAuth・API 権限・IAM: なし。

## 6. Series Placement

Series: lab-series
Reason: 自作ハードウェアとの組み合わせで、プロトコルと振る舞いを実測しながら固める実験的なプロジェクト。
M5 系の既存プロジェクト（m5-clock、m5-vehicle-logger）もここにある。

## 7. External Platform Constraints

### Mac（macOS 26 以降・Apple Silicon）

| 制約 | 根拠 | 設計への影響 |
|---|---|---|
| ローカルネットワークの許可が必要。Bonjour の探索・解決と LAN 宛ての TCP 接続が対象 | TN3179 | §5。拒否時は NWBrowser が `PolicyDenied`、NWConnection が `.waiting`（`localNetworkDenied`）になるので、それを状態表示に写す |
| 許可は未設定に戻せない | TN3179 | 試験の場所の判断（下記「試験環境」） |
| Terminal からアプリを直接起動すると自動で許可扱いになる | TN3179 | 試験は必ず `open` で起動する |
| 設定用 Wi-Fi に一度参加すると「記憶したネットワーク」に自動接続付きで登録され、iCloud キーチェーンで同期される。最後に参加したネットワークが最優先 | Apple サポート（Known networks、Wi-Fi の優先順位） | 設定の最後に消し方を案内する。試験後は `networksetup -removepreferredwirelessnetwork` で消す |
| 設定用 Wi-Fi が消えた後に元の Wi-Fi へ自動で戻るかは明記がない | 記載なし | Phase 0 で観測 |
| スリープ後に TCP 接続が残るかは文書化されていない | 記載なし | 起床通知で接続を確かめて張り直す。Phase 0 で観測 |
| 相手が黙って消えたとき、何秒で接続が失敗扱いになるかは文書化されていない | NWConnection の文書に記載なし | M5 の 1 秒ごとの応答と 5 秒の打ち切りで検出する |
| 窓の無いアプリは App Nap でタイマーが間引かれ得る | Energy Efficiency Guide | 接続中は `beginActivity(.userInitiatedAllowingIdleSystemSleep)` を使う。文書は有限の作業向けとしているため、常時使う理由を ADR に記録する |
| GPU 使用率を取る文書化された手段が無い | — | 非文書キー＋欠損時は非表示（§3） |

### M5（M5Stack BASIC v2.7・ESP32・arduino-esp32 3.x / ESP-IDF 5.5）

| 制約 | 根拠 | 設計への影響 |
|---|---|---|
| Wi-Fi は 2.4 GHz のみ。WPA2-PSK・WPA3-SAE（混在含む）に対応 | M5 仕様、ESP-IDF Wi-Fi Security | 5 GHz 専用・802.1X は対象外 |
| 見えない SSID への接続手順は文書化されていない | ESP-IDF の文書に記載なし | 対象外 |
| SoftAP のパスワードは 8 文字以上 | arduino-esp32 のソース | 12 文字を使う |
| SoftAP 動作中のスキャンは AP+STA に切り替わり、チャンネルは STA 側に合わせられる | ESP-IDF Wi-Fi ガイド、arduino-esp32 のソース | スキャンは SoftAP を出す前に 1 回だけ行う |
| Wi-Fi ドライバは既定で認証情報を NVS に平文保存する。NVS は既定で暗号化されない | ESP-IDF の NVS・Wi-Fi の文書、arduino-esp32 のソース | ライブラリ側の自動保存を切り、保存先を自前の 1 か所にする。鍵と Wi-Fi パスワードが平文で残ることは README に書く。フラッシュ暗号化は不可逆なので使わない。M5 を手放すときは設定を消すか `esptool erase-flash` |
| PSRAM が無い（SRAM 520 KB） | M5 仕様 | 全画面バッファを持たない。空きは Phase 0 で測る |
| ボタン A/B/C（G39/G38/G37）は起動時のモード判定に関与しない。G39 は Wi-Fi 使用時の割り込みに注意事項がある | M5 ピンマップ、ESP-IDF GPIO の文書 | 割り込みを使わず M5Unified のポーリングで読む。「B を押しながら起動」は安全 |
| Bluetooth は使わなければメモリが自動で解放される | arduino-esp32 のソース | 対応不要 |
| mbedTLS（ChaCha20-Poly1305・HKDF）は ESP-IDF に同梱 | ESP-IDF | 暗号はこれだけを使う |

### ネットワーク

- 端末どうしの通信を遮断するゲスト用 Wi-Fi や、mDNS を通さないネットワークでは使えない（対象外として README に書く）。
- 独自の部分は、標準の部品（ChaCha20-Poly1305、HKDF）の組み合わせ方に限る。組み合わせ方は Phase 1 の
  形式仕様で RFC と照合してレビューする。

## Discussion Log

1. **企画の再起動（2026-09-26）**: 汎用の通知表示器（m5-notify-deck、撤回済み）をやめ、システム情報の表示に特化する。
   コンパニオンが計測して送り、M5 は描画だけ、ボタンはページ切り替えだけ、という役割分担を運営者が指定。

2. **GPU**: 文書化された取得手段が無い。load-spinner と同じ非文書キー＋欠損時は非表示で合意。
3. **コンパニオンの形**: 最小のメニューバー常駐で合意。
4. **機種**: 前回と同じ M5Stack BASIC v2.7。
5. **伝送（1 回目: USB シリアル）**: 当初 USB シリアルを推奨。運営者が「M5 開発用に入れたドライバでは」と指摘したため実測した。
   接続中の BASIC（CH9102F、`1a86:55d4`）は OS 同梱の AppleUSBCHCOM が結合しており、WCH 製ドライバは読み込まれていなかった。
   macOS 26.6.2 の検証 VM でも同梱ドライバの照合表に `55d4` があることを確認した。
6. **伝送（2 回目: USB シリアルの却下）**: Espressif の文書から自動リセット回路の危険（RTS のみで再起動、DTR のみで書き込み待ち停止）を整理したところで、
   運営者が「デバッグポートと同じポートを使うのは無理がある」「書き込みとの同居は無理がある」と判断。BASIC の ESP32 は USB を持たず、
   USB のデータ経路が 1 本しかないため、構造的に避けられないと確認して却下した。
7. **伝送（3 回目: Wi-Fi）**: Wi-Fi を推奨。BLE は前回の失敗領域として推さなかった。
8. **Wi-Fi の設定方法**: TF カードの案は、運営者の実測（Mac から FAT32 の TF カードに書けない）で却下。
   M5 が設定用 Wi-Fi を出してブラウザのページで設定する案で合意した。
9. **キャプティブポータルの自動表示**: 一次資料の調査で、規格は HTTPS 必須・IP 直書き禁止で M5 では満たせず、
   代替の DNS の手法は Apple が判定方法を公開していないため、採らないことで合意した。
10. **M5 からの応答**: Mac が相手の消失に気づく時間が文書化されていないため、1 秒ごとの応答と 5 秒の打ち切りで合意した。
11. **試験の場所**: ローカルネットワークの許可が元に戻せないこと、VM に Wi-Fi が無いことを示し、運営者がこの Mac を選んだ。
12. **なりすまし**: 「同じ LAN からの偽の値は受け入れる」とした案を、運営者が「ダメ」と却下。
    鍵を共有するため、設定をブラウザからコンパニオンに移し、設定用 Wi-Fi の中で鍵を渡す形にした
    （パスワードは総当たりへの耐性のため 12 文字に延長）。通常時は ChaCha20-Poly1305 で暗号化と改ざん検知を行う。
    AirPlay 型の番号入力は PAKE が必要で CryptoKit に無いため、ブラウザのページで鍵を渡す案は履歴に残るため却下した。
13. **混線**: 運営者が「同じネットワークに複数の機器があると混線する」と指摘。先の状態表の「新しい接続が来たら古い接続を捨てる」が
    混線（よその Mac による切断）を起こすことを確認した。機器 ID と鍵で相手を決め、切り替えは最初のフレームが検証できたときだけ、
    パネル選択のメニューは廃止、という形で合意した。

- **A3（2026-09-26、通信仕様 v1）: 暗号の部品と設定時の相手。** パネルのビルド済みライブラリに ChaCha20-Poly1305 が
  組み込まれていないため、本文の ChaCha20-Poly1305（RFC 8439）はすべて **AES-256-GCM（NIST SP 800-38D）** に読み替える。
  鍵の導出は HKDF-SHA256 の Expand だけにする。設定時の相手は、Wi-Fi のインターフェースに固定した接続で、その Wi-Fi の
  ルーターのアドレスに限る（本文の「コンパニオンが設定中の M5 を見つける」は mDNS ではなくこの方法による）。
  LAN の上での妨害（表示を止めること）は残る危険として受け入れた。偽の値の表示と混線が起きないことは守る。
  根拠と却下した案は [ADR-0002](adr/0002-crypto-and-setup-binding.ja.md)、やり取りの詳細は [通信仕様 v1](protocol.ja.md)。
- **A4（2026-09-26、計測の実装）: コアの P/E を区別しない。** 論理 CPU の番号と種類（P/E）の対応は文書化されておらず
  （`sys/sysctl.h` が定めるのは種類ごとの数と「perflevel 0 が最も高性能」だけ）、IODeviceTree の `cluster-type` という
  文書に無い値でしか分からない。運営者の判断で区別しないことにした。本文 §2 のページ②「P コア / E コアを色分け」は
  「コアごとの棒グラフ（1 色）」に読み替える。通信仕様 v1 の `cores` は種別を持たない。
