# m5-system-panel 通信仕様 v2

> Status: Accepted（v1: 2026-09-26、v2: 2026-10-05 — 明るさの段階を足した。v1 との違いは §10）
> 関連: [RFP](m5-system-panel-rfp.ja.md)、[ADR-0001](adr/0001-phase0-premises.ja.md)、[ADR-0002](adr/0002-crypto-and-setup-binding.ja.md)、[ADR-0003](adr/0003-brightness.ja.md)

コンパニオン（Mac）とパネル（M5）の間のやり取りを定める。設定時（パネルの設定用 Wi-Fi の中）と通常時（家の
Wi-Fi の上）の 2 つのセッションがある。「しなければならない」「してはならない」は、実装とテストが従う規則である。

## 1. 用語と記法

| 語 | 意味 |
|---|---|
| パネル | M5Stack BASIC v2.7 上のファームウェア |
| コンパニオン | Mac のメニューバー常駐アプリ |
| 機器 ID | 設定のたびにパネルが作る 16 ビットの乱数を、大文字 16 進 4 桁の ASCII で書いたもの（例 `3F2A`） |
| 鍵 K | 設定のたびにパネルが作る 32 バイトの乱数 |
| B64 | RFC 4648 §4 の base64（標準の文字、`=` の詰め物あり）。**受け手は正規の形だけを受け付ける**：詰め物の数が正しく、詰め物に当たるビットが 0 で、文字種の外の文字（空白・改行を含む）が無いこと。それ以外は形の合わない行として扱う |
| `‖` | バイト列の連結 |
| `uint64_be(x)` | x を 8 バイトの符号なし整数として、上位のバイトから並べたもの |

- 乱数はすべて、パネルでは無線を起動した後の `esp_random()`（ADR-0001 決定 5）、コンパニオンでは
  `SecRandomCopyBytes` で作る。

## 2. 見つけ方（通常時だけ。mDNS / DNS-SD）

- パネルは通常時にサービス型 `_m5-system-panel._tcp` を公開する。インスタンス名は `m5-system-panel <機器ID>`。
- TXT レコード: `v=2`（通常時のセッションの版。`HELLO` の版と同じ）、`id=<機器ID>`。コンパニオンは `v` を候補の選別に使わない（版は `HELLO` で知る）。
- ポートは 47110 とし、SRV レコードで公開する。コンパニオンは SRV の値を使う。
- コンパニオンは、`id` が保存済みの機器 ID と一致する候補に**すべて**当たる。検証に失敗した候補（§4.1 の 7）は
  60 秒間は選ばない。同じ ID を名乗る偽の公開があっても、本物に届くようにするため。
- 探索の結果は「パネルがいるか」の判定に使わない（ADR-0001 決定 1）。
- 設定時は mDNS を使わない（§5.1）。

## 3. 行の形式（両セッション共通）

- TCP の上で ASCII の行をやり取りする。行は LF（0x0A）で終わる。CR は使わない。
- 1 行は LF を除いて **最大 1024 バイト**。超える行を受けた側は、接続を閉じなければならない。
- 行は 1 個の空白（0x20）で区切ったトークンの並び。空のトークンは作らない（空の値は、その項目で決めた記号で表す）。
- 決められた形に合わない行を受けた側は、何も返さずに接続を閉じなければならない（理由を相手に伝えない）。

## 4. 通常時のセッション

### 4.1 流れ

```
コンパニオン                                   パネル
    |---------------- TCP 接続 ------------------->|  パネルはここで 5 秒の時計を始める
    |<---- HELLO 2 <機器ID> <B64(Np)> -------------|  Np: 16 バイトの乱数
    |----- AUTH <B64(Nc)> ------------------------>|  Nc: 16 バイトの乱数
    |----- F <B64(フレーム c→p, ctr 0)> ----------->|  パネルが検証できたらセッション成立
    |<---- F <B64(フレーム p→c, ctr 0)> ------------|  コンパニオンが検証できたら「接続中」
    |----- F …（1 秒ごと）------------------------->|
    |<---- F …（1 秒ごと）-------------------------|
```

1. パネルは接続を受け付けたら、直ちに `HELLO 2 <機器ID> <B64(Np)>` を送る。Np は接続ごとに作る。
2. コンパニオンは、版が `1` でも `2` でもなければ「M5 のファームウェアが違います」とし、機器 ID が保存済みのものと違えば閉じる。
   そうでなければ Nc を作り、鍵を導出し（4.2）、`AUTH <B64(Nc)>` と最初のフレーム（計測値、ctr 0）を送る。
   以後このセッションでは、`HELLO` の版の形で計測値を送る（版 1 の相手には `bri` を付けない — §10）。
3. パネルは `AUTH` を受けて鍵を導出し、次の行のフレームを検証する。
   - 検証できたら、その接続をセッションとして成立させる。**別のセッションが成立していれば、その時点で古い方を閉じる**
     （置き換え。スリープから戻った Mac のつなぎ直しのため）。
   - 検証できない、または**受け付けから 5 秒以内に**検証できるフレームが届かないときは、この接続だけを閉じる。
4. 未成立の接続（受け付けたが、まだ検証できていないもの）は、同時に **2 本まで**。3 本目を受け付けたら、未成立のうち
   最も古いものを閉じる。**成立しているセッションは、未成立の接続の数を理由に閉じてはならない。**
5. パネルは、セッションが成立したら直ちに 1 回、以後 1 秒ごとに応答（4.4）を送る。成立したセッションで
   **10 秒間フレームが届かなければ、パネルはそのセッションを閉じる**（コンパニオンは 1 秒ごとに送る。スリープした Mac に
   応答を書き続けて送信の待ち行列が詰まるのを防ぐ）。コンパニオンは、最初の応答を検証できた時点で
   「接続中」と表示する（パネルが鍵を知っていることの確認）。
6. どちらの側も、フレームが検証できないとき、`ctr` が合わないとき、形の合わない行を受けたときは、何も返さずに接続を
   閉じなければならない。
7. コンパニオンは、`HELLO` の形が合わない相手、`AUTH` の後の最初の応答が検証できない相手を「検証に失敗した候補」とする（§2）。
8. コンパニオンの接続の見張り（`.preparing` 10 秒、応答なし 5 秒など）は ADR-0001 決定 1 に従う。

### 4.2 鍵の導出（RFC 5869 HKDF-SHA256、Expand のみ）

K は一様な 32 バイトの乱数なので、RFC 5869 §3.3 に従って Extract を省き、K をそのまま PRK として使う。

```
ctx  = 機器ID（ASCII 4 バイト） ‖ Np（16 バイト） ‖ Nc（16 バイト）
K_cp = HKDF-Expand(PRK = K, info = "m5-system-panel/1 c2p" ‖ ctx, L = 32)
K_pc = HKDF-Expand(PRK = K, info = "m5-system-panel/1 p2c" ‖ ctx, L = 32)
```

- 文字列は ASCII で、終端の NUL を含まない（`"m5-system-panel/1 c2p"` は 21 バイト）。
- ラベルの `/1` は鍵とフレームの作り方の版で、`HELLO` の版（計測値の形の版）とは別に数える。v2 でも変えない（ADR-0003）。
- 方向ごとに別の鍵を使う。コンパニオンは K_cp で暗号化して K_pc で復号し、パネルはその逆を行う。
- 両側とも自分の新しい乱数（パネルは Np、コンパニオンは Nc）を毎回混ぜるので、どちら側に古いセッションを録って
  送り返されても、鍵が変わって検証に失敗する。攻撃者が相手側の乱数を選んでも、鍵はセッションごとに一意である。

### 4.3 フレーム（NIST SP 800-38D AES-256-GCM）

```
行          = "F " B64( C ‖ T )
nonce (12)  = 0x00000000 ‖ uint64_be(ctr)
AAD         = "m5-system-panel/1"（ASCII、17 バイト）
C, T        = AES-256-GCM-Encrypt(key = その方向の鍵, nonce, AAD, P)    T は 16 バイト
```

- `ctr` は方向ごとに 0 から始め、フレームを 1 つ送るたびに 1 増やす。nonce は行に載せない（受け手は自分で数える）。
  TCP は順序を保つので、受け手は期待する `ctr` で復号し、失敗すれば閉じる。再送・順序の入れ替え・欠落・反射
  （相手のフレームを送り返すこと。方向ごとに鍵が違う）は、すべてここで失敗する。
- 1 つの方向の鍵は 1 つのセッションでしか使わない。鍵ごとに nonce は `ctr` で一意になる（SP 800-38D §8.2.1 の
  決定的な作り方）。
- 最後に送ってよいフレームは `ctr` = 2^32 − 1。送り手はそれ以上送らずに閉じ、受け手は期待する `ctr` が 2^32 に
  なったら閉じる（1 秒に 1 フレームなら 136 年で、実際には起きない）。
- 平文 P は ASCII で最大 700 バイト。送り手は長さを確かめなければならない。行は最大 `2 + 4⌈(700+16)/3⌉ = 958` バイト。

### 4.4 平文の中身

平文はトークンを 1 個の空白で区切った 1 行（LF は含まない）。先頭のトークンが種類。項目の順序は下の表のとおり固定し、
欠けたり重複したりしたものは形が合わないとする。**受け手は形だけを確かめ、値どうしの関係（使用量 ≤ 搭載量など）は
確かめない。** 形が合わないフレームは、検証に成功していても、受け手は閉じなければならない。

**計測値（コンパニオン → パネル）**

```
M seq=<n> cpu=<pct1> cores=<pct0>[,<pct0>…] gpu=<pct1|-> mem=<n>/<n> app=<n> wired=<n> comp=<n> swap=<n> press=<0|1|2> if=<name|-> rx=<n> tx=<n> bri=<1-5>
```

版 1 の形は、最後の `bri` が無いもの（§10）。

| 項目 | 形 | 意味 |
|---|---|---|
| `seq` | `<n>` | 計測値の番号。セッションごとに 0 から 1 ずつ増やす。受け手は連続を確かめない（順序は `ctr` が守る） |
| `cpu` | `<pct1>` | 全体の使用率 % |
| `cores` | `<pct0>` をカンマ区切り、1〜64 個 | コアごとの使用率（論理 CPU の番号順。P/E の種別は送らない — RFP 追補 A4） |
| `gpu` | `<pct1>` か `-` | GPU 使用率。取れないときは `-`（パネルは GPU の表示を消す） |
| `mem` | `<使用バイト>/<搭載バイト>` | |
| `app` `wired` `comp` | `<n>` バイト | メモリの内訳（アプリ・固定・圧縮） |
| `swap` | `<n>` バイト | スワップの使用量 |
| `press` | `0` 通常・`1` 警告・`2` 危機 | メモリの圧迫度 |
| `if` | `[A-Za-z0-9]{1,15}` か `-` | 主に使っているインターフェースの BSD 名（例 `en0`）。無いときは `-` |
| `rx` `tx` | `<n>` バイト/秒 | 受信・送信の速度 |
| `bri` | `1`〜`5` の 1 桁 | 画面の明るさの段階。`1` が最も暗く `5` が最も明るい。段階ごとの実際の明るさはパネルが決める（ADR-0003）。版 2 だけ |

- `<n>`: 10 進の整数 0〜2^63 − 1。先頭に 0 を付けない（`0` は可）。符号は付けない。
- `<pct1>`: `0.0`〜`100.0`。整数部 1〜3 桁（先頭に 0 を付けない。`0.5` は可）と小数部ちょうど 1 桁（例 `7.5`、`100.0`）。
- `<pct0>`: `0`〜`100` の整数（先頭に 0 を付けない）。
- 最も長くなる正当な平文は 530 バイト（コア 64 個がすべて `100`、整数がすべて 19 桁、`if` が 15 文字、`bri=5`）。版 1 では 524 バイト。

**応答（パネル → コンパニオン）**

```
A seq=<n|-> up=<n>
```

- `seq` はパネルがこのセッションで最後に受け取った計測値の `seq`。まだ受け取っていなければ `-`。
- `up` はパネルの起動からのミリ秒。
- パネルはセッションが成立している間、1 秒ごとに送る。

## 5. 設定時のセッション

### 5.1 どの相手と張るか

設定時のセッションでは、家の Wi-Fi のパスワードと鍵 K が平文で流れる。**コンパニオンは、次のすべてが成り立つときだけ
設定時のセッションを張らなければならない。**

1. 接続を Mac の Wi-Fi インターフェースに固定する（Network.framework の `requiredInterface`）。
2. 接続先は、その Wi-Fi インターフェースのルーターのアドレス（DHCP で受け取ったもの）の 47110 番とする。mDNS の
   結果や、利用者が入力したアドレスは使わない。
3. 最初の行が `SETUP 1 <機器ID>` である。

理由：Mac の Wi-Fi のルーターになれるのは、Mac が参加しているアクセスポイントだけである。設定用 Wi-Fi のパスワードは
パネルの画面にしか出ず、WPA2 ではパスワードを知らないアクセスポイントは Mac との接続を確立できない（WPA2 の相互認証
からの推論。実測はしていない）。家の LAN の誰かが `SETUP` を送っても、それは Wi-Fi のルーターのアドレスからではないので
張らない。Wi-Fi の名前（SSID）で確かめる方法は、特権の無いアプリからは SSID が伏せ字になり読めないため採らない
（Phase 0 で実測。ADR-0002）。

- コンパニオンは、Wi-Fi のインターフェースの状態が変わったときに 2・3 を試し、成り立てばメニューに「設定を始める」を出す。
  利用者が選ぶまで `LIST` 以降は送らない。

### 5.2 流れ

```
コンパニオン                                   パネル（設定用 Wi-Fi のルーター）
    |---- TCP 接続（Wi-Fi に固定、ルーター:47110）-->|
    |<---- SETUP 1 <機器ID> ----------------------|
    |----- LIST ---------------------------------->|  省略してよい（手入力のとき）
    |<---- NET <rssi> <auth> <B64(ssid)> …--------|  設定用 Wi-Fi を出す前に探した結果
    |<---- END ------------------------------------|
    |----- JOIN <B64(ssid)> <B64(password)|-> ---->|
    |<---- KEY <B64(K)> ---------------------------|  K はここで作る
    |----- STORED -------------------------------->|  コンパニオンが K を「仮」として保存した
    |<---- DONE -----------------------------------|  パネルが NVS に保存した → 再起動
```

- `NET` は最大 20 行。受信の強い順に並べる。長さ 0 の SSID（見えないネットワーク）は入れない。同じ SSID は
  最も強いものだけを入れる。
- `rssi` は dBm の整数（`-?[0-9]{1,3}`。先頭に 0 を付けず、`-0` は使わない）。`auth` は `open` `wpa2` `wpa3` `wpa2wpa3` `other` のいずれか。
- SSID は 1〜32 バイトの任意のバイト列（UTF-8 とは限らない）。B64 で運ぶ。
- パスワードは 1〜63 バイトなら B64、認証の無いネットワークなら `-`。
- パネルは `JOIN` を受けてから K を作って `KEY` を送り、`STORED` を受けるまで何も保存しない。`STORED` の前に
  接続が切れたら、K と `JOIN` の内容を捨てる。
- パネルは `STORED` を受けたら、Wi-Fi の設定・機器 ID・K を NVS に書き、`DONE` を送って再起動する。書き込みに
  失敗したら `DONE` を送らずに閉じ、画面に失敗を表示する。
- コンパニオンは、`KEY` を受けたら K を「仮」としてキーチェーンに保存して `STORED` を送る。`DONE` を受けたら、
  それまでの登録（機器 ID と鍵）を新しいものに置き換える。`DONE` の前に切れたら、仮の K を捨て、それまでの登録を残し、
  「設定を完了できませんでした」と表示する（パネルが保存を終えていた場合は、利用者が設定をやり直す）。
- キーチェーンの項目は同期させない。同期されると、同じ利用者の別の Mac が同じ鍵でセッションを奪い合うため。
  ファイル型のキーチェーン（macOS で `kSecUseDataProtectionKeychain` を指定しない SecItem の既定）に保存する。
  iCloud キーチェーンはデータ保護キーチェーンにしかなく、ファイル型の項目は同期されない。データ保護キーチェーンの
  アクセスグループにはプロビジョニングプロファイルが要り、このアプリは持たない（TN3137）。
- 設定時のセッションは同時に 1 つだけ。パネルは、行が届かない時間が次を超えたら閉じる：利用者の操作を待つ間
  （`SETUP` を送ってから `JOIN` を受けるまで。ネットワークを選びパスワードを打つ時間）は 10 分、コンパニオンの応答を
  待つ間（`KEY` を送ってから `STORED` まで）は 60 秒。
- パネルは、設定時のセッションでは通常時の行を送らず、通常時のセッションでは設定時の行を受け付けない。

### 5.3 設定用 Wi-Fi のパスワード

- 文字は `abcdefghjkmnpqrstuvwxyz23456789`（31 種。見分けにくい文字を除く）から 12 文字。1 文字ごとに `esp_random()` の
  値を、31 の倍数に収まる範囲だけ受け付けて（範囲外は引き直す）選ぶ。偏りは無い。情報量は約 59.4 ビット。
- 設定を始めるたびに作り直す。

## 6. 誤りの扱い

| 状況 | パネル | コンパニオン |
|---|---|---|
| 行が 1024 バイトを超える／形が合わない | 閉じる | 閉じる |
| `HELLO` の版が 1 でも 2 でもない | — | 閉じて「ファームウェアが違います」 |
| `HELLO` の機器 ID が保存済みと違う | — | 閉じる（別のパネル） |
| 受け付けから 5 秒以内に検証できるフレームが無い | この接続だけ閉じる | — |
| 未成立の接続が 3 本目 | 未成立のうち最も古いものを閉じる | — |
| フレームが検証できない／`ctr` が合わない | 閉じる（成立前なら既存のセッションは残す） | 閉じ、その候補を 60 秒間避ける |
| 最初の応答が検証できない | — | 同上。「接続中」にしない |
| 5 秒応答なし | — | ADR-0001 決定 1 |
| 成立したセッションで 10 秒フレームなし | 閉じる | —（次の接続でつなぎ直す） |
| 設定時の相手が Wi-Fi のルーターでない | — | 張らない |

## 7. 見本データ（テストの既知解）

実装の前に、両側のテストが使う見本データを `testdata/protocol.json` として作る。

- 外部の既知解: RFC 5869 の Test Case 1〜3（HKDF-SHA256。Expand だけでなく Extract も含むが、部品の確認として使う）と、
  AES-256-GCM の既知解（NIST CAVP の gcmEncryptExtIV256 から、96 ビットの nonce と AAD を持つもの）。
- この仕様の既知解: 固定した K・機器 ID・Np・Nc から導いた K_cp・K_pc、`ctr` = 0・1 のフレームの行、計測値と応答の平文、
  最も長い正当な平文（版 1 は 524 バイト、版 2 は 530 バイト）。版 2 の `HELLO` と計測値のフレームは、版 1 と同じ入力から作る。コンパニオンのテストで生成して固定し、パネルは実機のテスト用スケッチで同じ値を照合する。
- 拒否すべき例: 形の合わない行、正規でない B64、検証できないフレーム、`ctr` の飛び、1025 バイトの行、`cores` が 65 個、
  値の範囲外（`cpu=100.1` など）。両側が閉じることを確かめる。
- 版 2 の拒否すべき計測値: 版 1 の拒否例それぞれの末尾に ` bri=3` を足したもの（元の理由で拒否されることを確かめる）と、
  `bri` に固有のもの（無い、`0`、`6`、`03`、空、`-`、2 回、`tx` より前、末尾の空白）。版 1 の読み手は `bri` の付いた行を拒否する。

## 8. 残る危険（受け入れるもの）

- **妨害は防げない。** LAN の上で悪意のある相手は、未成立の接続を張り続ける・TCP の切断を偽造する・ARP を偽装する、
  といった方法で、表示を止めることができる。**他人の値を表示させること、ほかのパネルや Mac と混線することは無い**
  （検証できない値は表示せず、成立したセッションは検証できたフレームでしか置き換わらない）。
- **設定時の通信は、設定用 Wi-Fi の暗号だけで守られる。** 設定用 Wi-Fi に参加する手順を録られ、パスワード（約 59.4 ビット）を
  手元で総当たりされると、録られた設定時の通信から K と家の Wi-Fi のパスワードが分かる（前方秘匿性は無い）。
  WPA2 のパスワードの確かめには PBKDF2-HMAC-SHA1 を 4096 回かけるので、1 秒に 100 万回試せると仮定しても平均で
  1 万年以上かかる（推論。試行の速さは測っていない）。
- 設定用 Wi-Fi のパスワードは、参加した Mac のシステムのキーチェーンに残る（ADR-0001 実測 2）。使い捨てなので
  設定の後は意味を持たないが、残骸にはなる。消し方の案内は ADR-0001 決定 4 に従う。
- パネルの NVS の鍵と Wi-Fi のパスワードは平文（RFP §7）。

## 9. この仕様の外にあるもの

- パネルの画面の描き方、ページ、ボタン。
- コンパニオンの計測の方法。
- 複数のパネル、複数の Mac（RFP で対象外）。
- `bri` の各段階の実際の明るさと、データが来ないときの減光（パネルの描き方の一部。ADR-0001・ADR-0003）。

## 10. 版の違い

| 版 | 出したもの | 違い |
|---|---|---|
| 1 | v0.1.0〜v0.1.1 のファームウェア | 最初の版 |
| 2 | v0.2.0 からのファームウェア | `HELLO` の版が `2`、TXT の `v=2`、計測値の末尾に `bri=<1-5>` |

- 版が変えるのは **`HELLO` と TXT の版の値と、通常時のセッションの計測値の形**だけ。鍵の導出・フレーム・応答と、
  版の値に関わらない誤りの扱いは同じで、ラベルの `/1`
  （§4.2・§4.3）も変えない。設定時のセッション（§5、`SETUP 1`）は変わらない。
- パネルは自分の版の形だけを受け付ける（版 2 のパネルは `bri` の無い計測値を形が合わないとして閉じる）。
- コンパニオンは版 1 と版 2 の両方とつなぎ、`HELLO` の版に合わせた形で送る。版 1 のパネルには明るさを送れない。
- 版 2 だけを知るパネルに版 1 のコンパニオンがつなぐと、`HELLO 2` を受けたコンパニオンが「ファームウェアが違います」とする。
- 版の書き換え（`HELLO` は暗号で守られない）は、どちらの向きでも形の合わない計測値か応答の不在になり、接続が切れるだけで
  ある（妨害。§8 で受け入れたものと同じ）。他人の値の表示にはならない。
