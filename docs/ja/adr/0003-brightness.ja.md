# ADR-0003: 画面の明るさは Mac が持ち、計測値と一緒に毎秒送る

| Field | Value |
|-------|-------|
| Status | **Accepted** |
| Date | 2026-10-05 |
| Binds | m5-system-panel |
| Decision makers | nlink-jp maintainers |
| Triggered by | 運営者の要望「M5 の画面の明るさを、コンパニオンから設定できるようにしたい」 |

## Context

v0.1 のパネルは、明るさを `M5.Display.setBrightness(128)` の固定で点け、データが 5 分届かないと消す（ADR-0001）。
明るさを変える手段は無い。

設計の前に確かめたこと:

- **通信仕様 v1 は形に厳しい。** 計測値の項目は順序も数も固定で、形の合わない平文を受けた側は閉じる（§4.4）。
  v1 のパネルに項目を 1 つ足した計測値を送ると、接続のたびに閉じられる。コンパニオンは `HELLO` の版が `1` でない
  相手を「ファームウェアが違います」として拒む（§4.1）。どの形で足しても、版を上げる変更になる。
- **BASIC のバックライトは、M5GFX の既定では暗い側が無い**（knowledge `embedded.md`「M5Stack BASIC のバックライトは
  44.1 kHz の PWM では暗くならない」、2026-09-25 の実機観測）。M5GFX は GPIO32 を 44.1 kHz・9 ビットで動かし、
  1% でも十分に読める明るさになる。同じチャネルを `ledcChangeFrequency(32, 1000, 14)` で 1 kHz・14 ビットに移し、
  `(割合/100)^2.2` を全点灯（16383）に掛けると、暗い側まで段がほぼ均等に効いた。M5GFX 0.2.27 は arduino-esp32 3.x で
  `ledcAttach(pin, freq, bits)` を使う（`Light_PWM.cpp`）ので、端子の番号でそのチャネルを動かせる。
- **コンパニオンはメニュー型の `MenuBarExtra`**（RFP §2）。メニューの項目に連続のスライダーは馴染まない。

## Decision

1. **明るさの設定は Mac が持つ。** コンパニオンが UserDefaults に保存し、計測値の行の末尾に `bri=<1-5>` として
   毎秒載せる（通信仕様 v2 §4.4）。パネルは保存しない（NVS に書かない）。確認応答・再送・フラッシュへの書き込みが要らず、
   設定の正本が 1 か所になる。パネルが再起動しても、次のフレームで元に戻る。
2. **送るのは段階（1〜5）で、PWM の値ではない。** 段階ごとの実際の明るさはパネルが決める。バックライトの性質（周波数・
   ビット数・曲線）はパネルの事情で、コンパニオンに持ち込まない。
3. **パネルは 1 kHz・14 ビットに移し、`(割合/100)^2.2 × 16383` で点ける**（knowledge の適用方法どおり）。機種が BASIC で
   ない、または `ledcChangeFrequency` が失敗したときは、M5GFX の `setBrightness` に割合を比例で渡す。段階の割合は
   実機で見て決めた（下の表）。
4. **最初のフレームが届くまでは段階 3 で点ける**（起動直後・設定モード・待ち受け）。コンパニオンの既定も段階 3。
   受け取った段階は、再起動まで RAM に持つ（セッションが切れても、減光から戻っても、その段階で点ける）。
5. **データが来ないときの減光は変えない**（5 分で消し、ボタンか値の受信で点ける — ADR-0001）。点けるときに選んだ段階に戻す。
6. **通信仕様を v2 にする。** パネルは `HELLO 2` を名乗り、v2 の形だけを受け付ける。コンパニオンは版 1 と 2 の両方とつなぎ、
   `HELLO` の版の形で送る。版 1 のパネルにつながっている間、メニューの明るさは選べなくし、ファームウェアの更新が要ると示す。
   鍵の導出とフレームのラベル（`m5-system-panel/1`）は変えない — 変わるのは計測値の形だけで、版の書き換え（`HELLO` は
   暗号で守られない）はどちらの向きでも接続が切れるだけ（仕様 §8 で受け入れた妨害と同じ）だから。
7. **メニューは「明るさ」のサブメニューで 5 段階から選ぶ**（「1（暗い）」〜「5（明るい）」）。

段階の割合（実機で決めた値。2026-10-05、BASIC v2.7 1 台・運営者 1 人の判断）:

| 段階 | 割合 | 14 ビットの値 |
|---|---|---|
| 1 | 25% | 776 |
| 2 | 40% | 2182 |
| 3 | 55% | 4397 |
| 4 | 65% | 6350 |
| 5 | 75% | 8700 |

決め方: 最初に 10 / 30 / 50 / 75 / 100% を試し、「段階 1 は暗すぎる、段階 3 は少し暗い、段階 4（75%）が最大で
段階 5 は明るすぎる」との判断を得た。上限を 75% に、下限を 25% に寄せた 2 回目の値で「どれもちょうどよい、間隔も均等」と
なった（ADR-023 の「実機の手直しは 2 回目で止める」の範囲内）。全点灯（100%）は選べない。

## Consequences

- 明るさを変えるには、アプリとファームウェアの両方の更新が要る。新しいアプリは古いファームウェアとも動く（明るさは選べない）。
  古いアプリと新しいファームウェアの組み合わせは「ファームウェアが違います」になる。README に更新の順序を書く。
- 接続の前（起動・設定モード・待ち受け）の明るさは選べない。段階 3 で点く。
- 毎秒 6 バイト（` bri=3`）増える。最長の平文は 530 バイトで、上限 700 バイトに収まる。
- 全点灯は選べない（最も明るい段階 5 で 75%）。明るい部屋で足りないという声が出たら、段階 5 だけを見直す。
- 1 kHz・14 ビットに移せたときは、点灯・消灯とも `setBrightness` を呼ばず、自前の PWM の書き込みで行う（`setBrightness` は
  9 ビットの値を書いてしまう）。移せなかったとき（BASIC で `ledcChangeFrequency` が失敗した場合を含む）はチャネルが
  9 ビットのままなので、`setBrightness` を使う。

## Alternatives considered

| 案 | 採らない理由 |
|---|---|
| パネルの NVS に保存し、変えたときだけ送る | 確認応答・再送・保存の失敗の扱いが増え、設定の正本が 2 か所になる。接続前から設定の明るさになる利点は小さい |
| PWM の値（0〜255 など）を送る | バックライトの周波数や曲線というパネルの事情がコンパニオンに漏れる。機種や点け方を変えるとアプリも変わる |
| スライダーで連続に選ぶ | メニュー型の `MenuBarExtra` に馴染まない。窓型にするか別の窓を開くことになり、常駐アプリが重くなる |
| 新しい種類のメッセージ（`B bri=…`）を足す | v1 のパネルは知らない種類で閉じるので、版を上げることは避けられない。毎秒の計測値に載せる方が状態を持たない |
| ラベルを `m5-system-panel/2` に上げる | 鍵とフレームの作り方は変わらない。版の食い違いは今でも接続が切れるだけで、上げても検出が少し早くなるだけ。見本データの鍵とフレームを作り直すことになる |
| ボタンで明るさを変える | ボタンはページ送り専用（RFP §2）。運営者の要望は「コンパニオンからの指令でよい」 |
